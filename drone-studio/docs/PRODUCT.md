# Lucidity Drone Studio — product direction

**v0.4 · September 27, 2026 · Immersive viewer and expert authoring · Open for input**

**Platform direction updated October 14, 2026:** the [Lucidity product brief](PRODUCT_BRIEF.md) establishes the broader agent-first drone platform for experts managing varied builds. The expert-depth principle below now applies across that platform. This document preserves the Drone Show workspace's detailed direction and implementation record; its studio-only audience and earlier hardware sequencing no longer define the scope of Lucidity as a whole.

## Operating model, confirmed with you

Build the tool for the expert who wants unusually ambitious, precise work. Expose the objects, coordinates, animation channels, timing, source, and programmatic operations needed to make it. AI closes the learning gap by helping anyone operate that same tool.

A recipe picker cannot be the creative ceiling. A formation is a starting point. Every drone must remain independently editable; generated work must be inspectable and changeable at the same level of detail as manually authored work. The viewport is an editing surface, not a passive playback window.

The experience should have the precision and pleasure of working in a mature Mac creative application, with Final Cut Pro as a reference for timing and workspace ergonomics and Blender as a reference for spatial manipulation. This does not imply matching either product’s complete feature set in the MVP.

The preview should also feel like being inside the show. The default audience view places the artist at human eye level within the authored space, able to turn around and look overhead. A stage and surrounding audience provide orientation and scale. Design mode remains the precise workspace for selecting and manipulating the choreography.

| Confirmed choice    | Direction                                                                                       |

| Audience            | Creative studios, directors, and expert show designers                                          |
| Capability baseline | Granular professional authoring; AI makes its depth approachable                                |

## The creative model

A show is a timed composition of identifiable lights in space. A designer can start from a seed formation, write explicit point data, or generate a design with code. A point has a stable drone ID, an arbitrary spatial position, RGB color, brightness, and flashing parameters. Those properties can change over time through independent channels.

Groups are useful selection sets rather than a requirement to treat the whole fleet uniformly. A designer should be able to animate one drone, recolor a region, rotate a selected constellation, create phased light patterns, or change the fleet size without losing authored data on temporarily inactive IDs.

An agent should have the same primitives. “Make this cluster rise, turn amber, and ripple with the beat” should resolve to inspectable edits on selected IDs and channels. It should be possible to switch between a prompt, direct manipulation, numerical input, timeline keys, and source without translating between incompatible documents.

The inspector follows the scene under the playhead when drones are selected. A key’s timestamp is relative to its scene, so moving a scene moves its animation. Trimming a scene preserves later keys as dormant data; extending the scene exposes them again. Incoming transitions blend toward the animated target pose. The source and inspector expose those semantics rather than hiding them.

**Select from view** connects immersive viewing to granular editing. The artist can find every active drone inside the camera frame, in a stage-relative quadrant, or overhead, filtered to lights on/off/either and optionally the current selection. The query captures exact time, pose, lens, aspect, and criteria; the displayed result keeps that identity even if form inputs change. Explicit Replace or Add transfers all matching IDs to the existing inspector without moving lights or changing show history. Add preserves existing members rather than toggling them. The selection count is visible in Viewer; Design retains the geometric selection rings and transform gizmos.

**Preview matches** reveals the entire measured group in Viewer before selection changes. Thin rings identify even unlit drones without brightening the show. Matched IDs stay fixed while their displayed positions follow the current show clock; the card labels the captured and current times. Hide/Show and Clear return to the immersive render, and explicit Replace/Add uses the same full group. Recall restores the captured camera and time only when requested. Audience marks suspend in Design, clear when the show changes, and stay out of rendered review exports.

The agent has the same query with bounded ID pages and complete counts. A nonempty result also carries a temporary target for the complete matching set, allowing one granular color, flash, transform, or keyframe operation without listing every ID in model context. The resulting proposal expands every affected ID for inspection. Targets expire after any successful draft edit, so further changes require a fresh query. The artist's original selection stays intact. Geometric inclusion and evaluated light state describe one frame, not occlusion, perceived brightness, or continuous coverage.

Viewer 360° begins at the center of the authored space, 1.7 m above ground, with the reference stage 70 m north and its front facing south. Dragging or using the focused 3D canvas's arrow keys changes where you look while your position stays fixed. Home faces the stage; Stage, Left, Right, Behind, and Sky controls provide quick direction changes. The viewer can choose Center, Rear, Left, or Right audience positions, enter East/North coordinates, and adjust eye height or field of view. A plan allows dragging or keyboard positioning of both viewer and reference stage within ±500 m. The stage front has its own compass heading, 0°–359°, with 180° as the default. Changing these viewing preferences leaves every drone's authored geometry and animation unchanged.

The venue and cinematic appearance help judge composition from a human perspective. Explicit **Save**, **Recall**, and **Remove** actions manage up to 12 local views per project, each named with up to 48 characters. A bookmark captures the exact viewer position, eye height, yaw/pitch, vertical field of view, and reference stage position/heading. It does not capture the playhead or appearance settings, so the same saved view can be used at any point in the show. Views are not autosaved or automatically restored. Invalid or unrecognized local storage is preserved with an error rather than replaced.

Bookmarks are device-local preferences separate from the choreography. They do not create project revisions or change exported content. The reference venue remains a visual aid, not a portable scene asset or a description of a real operating site; Design retains its orbit camera and spatial editing controls.

**Audience camera audition** adds a temporary viewing move from the current camera or a saved view to another saved view. Preparation captures the endpoints and chosen 1–30-second duration without moving the camera. Play, Pause, Start, scrub, and Replay operate an independent camera clock, so the artist can hold the show still or play it while reviewing the move. Smooth motion eases in and out; Linear keeps a steady interpolation rate. Yaw takes the shortest turn, with exact opposite directions turning clockwise. Position, eye height, pitch, and vertical field of view also interpolate. The reference stage never moves: both endpoints must share its current layout.

The prepared move stays separate from later form edits and bookmark changes. Successful preparation reveals Play in the compact panel; failed preparation preserves the last valid move. Direct looking, wheel zoom, direction buttons, bookmark recall, or viewer/stage edits immediately take over and clear the move. Closing the panel or opening viewing settings pauses at the settled pose. Design, a different project, renderer failure, or closing the Stage clears it. Before/Draft switches within the same project retain its trajectory and clock. Frame capture pauses camera and show clocks before capturing their current pose/time. This is private rehearsal: no camera track, bookmark, show revision, audio timing, or export is written.

**Analyze move** turns the prepared camera path into a composition report. Opening pauses camera and show playback; the artist explicitly maps camera time from zero to the move's duration onto a show start/end interval. Equal show endpoints hold the choreography. A chosen 2–12 samples includes both exact endpoints, displaying camera elapsed time separately from show time and exposing each sampled position, direction, lens, stage placement, and geometric/light totals. Summary counts are minimum, maximum, and arithmetic sampled mean of lit drones in frame, with earliest ties. These are discrete measurements, not a continuous visibility or aesthetic assessment.

Run captures the path and projection aspect without moving the viewer. Cancellation and failed reruns preserve the last complete report; document changes invalidate current work and mark older results stale. Inspect is the explicit action that recalls a reported camera pose, seeks the local show transport, closes the report, and clears the previous camera rehearsal. It does not change the saved show. The agent's read-only `inspect_camera_move` uses the same calculation on its draft and captured viewpoints, with no live camera movement or image input.

**Compare views** turns those viewpoints into a composition check across a selected scene or custom show-clock range, with the span also shown in beats. It captures the selected poses when Run is pressed, then samples equally spaced moments including both endpoints. The report compares minimum, maximum, and arithmetic sampled-mean counts of lit drones in each camera frame. Selecting a row reveals front/right/rear/left, overlapping overhead, geometric in-frame, and lit-in-frame counts for every listed moment. **Inspect** explicitly recalls that report's pose and seeks to its moment. Calculation itself does not move the camera. It can be cancelled; failed/cancelled reruns preserve the previous report, and show edits mark older reports stale and disable their Inspect actions. The same flow is available within the independent study and draft previews.

The **360° study** entry opens a separate example without replacing the current show. _All around you_ surrounds an audience at the origin with cyan/violet/gold ribbons and an overhead crown. Its 48-second preview has its own playhead, chapter shortcuts, and silent playback; the main show's music pauses. An editable download is available for later use. This is distinct from **Open the expert study**, which opens the editable Prismatic project in the main workspace.

## AI is the accessibility layer

The intended agent reads the current selection, playhead, source, music, and design review; chooses expert operations; previews a change; explains its choices; and leaves editable results. It should help users learn exact controls and progressively take over repetitive work.

**Current status:** a bounded, provider-neutral agent harness and server-side OpenAI Responses adapter are implemented. The assistant reads scene/selection/time context, discovers the real command schemas, stages private edits, reviews them, and returns an inspectable proposal. The artist can preview it in an isolated 3D viewer and apply it as one undoable edit; stale proposals are blocked. A clearly labeled scripted rehearsal exercises the same tools without an API key. Live model quality and choreography competence remain untested until the key is provided. The CLI brief interpreter remains template-based. See [AGENT_HARNESS.md](AGENT_HARNESS.md) and [tooling research](AGENT_RESEARCH.md).

Proposal preview has **Before** and **Draft** versions within one persistent canvas. Both use the same show-global playhead, camera, lens, appearance, and reference venue. Opening captures the main viewer's current audience pose; subsequent look-around changes apply equally to either version. A silent shared transport spans the longer version, and a shorter version's last frame is explicitly labelled as held after its endpoint. This makes retiming visible without stretching one version to match the other. Version switches do not author or apply changes. The artist can still use read-only Design mode and the numerical audience comparison for the displayed version.

Artists can **Expand comparison** to give the immersive stage the available browser viewport. The version switch and transport stay in view, with detailed audition, navigation, and evidence controls behind a **Review controls** tray. Expansion is an application layout rather than a browser fullscreen requirement. The same canvas, audience pose, clock, markers, and audition state remain mounted through expansion and restoration. Escape dismisses a nested review dialog first, then restores the expanded layout before closing the comparison.

The audience preview also offers optional **Show marks** for the complete union of explicit per-drone command targets. Before and Draft each report active and inactive counts against their own fleet; IDs are never silently truncated to a page or current selection. The union covers all scenes, including reset commands, no-ops, and keys outside the current playhead. It identifies command intent, not a measured visual difference. Broad scene/show operations are counted separately without inventing target rings. Markers start off, follow current positions, suspend in Design, work in the expanded comparison, and remain excluded from captured review stills. These controls cannot select, edit, or apply the proposal.

The comparison names the currently playing scene and local time on both sides. Changed-scene navigation helps the artist find additions, removals, reordered scenes, and authored changes without scrubbing the whole show. Each side offers its own labelled show-time landmarks; choosing one pauses and shows that version while retaining the camera. Landmarks describe authored scene/key/transition locations, not measured onset of a visible difference. A shifted but otherwise unchanged scene is not reported as edited, and whole-show changes such as fleet size or tempo are identified separately.

Private audition controls let the artist repeat a show-time interval while comparing versions and looking around. An enabled range plays from In up to Out, wrapping back to In with delayed-frame overshoot preserved. Scene/transition presets enclose the selected scene's intervals across both documents; a first scene or cut has no incoming blend interval. Playback speed ranges from 0.25× to 2× and changes viewing speed only. Disabling Loop retains the range and restores full-show playback. Free paused seeks can inspect outside the range, with the next Play returning to In. Invalid bounds retain the committed range. Loop and rate belong to the comparison session, not authored choreography, exports, or the main transport.

Measured review moments connect the agent's actual audience inspections to this private preview. Each names Before or Draft, the captured viewpoint, show time, lit-in-frame count, and source inspection. An explicit Open action pauses, seeks, and recalls the captured audience pose on the same canvas, retaining the audition settings. Intermediate draft measurements cannot be presented as final results. Comparison extrema describe only the sampled moments; they are not aesthetic judgments or continuous coverage claims. The list stays collapsed by default and is absent when no matching evidence exists.

Camera-path evidence appears in this same list with both clocks: camera elapsed time and show time, plus the sample number and easing. The minimum and maximum use exact sampled poses and their captured framing. Opening one explicitly recalls that moment; it does not play a camera move. Evidence is checked against the completed run's captured endpoints and final proposal, and older traces without that context remain unlinked.

After opening a moment, **Captured frame** offers its recorded aspect as an explicit viewer toggle. The normal viewport is the default. With the toggle enabled, a centered frame fits within the available canvas area through resizing, fullscreen, and Before/Draft changes. Camera direction, lens, and playback remain freely adjustable; the historical count applies only at the recorded pose/time. A later opened moment supplies its own aspect and keeps the toggle choice. Design temporarily uses the full canvas; returning to Viewer restores the framing choice. This display setting does not author camera keys or alter the show.

**Capture audience frame** turns the displayed audience view into a local review still. Capture pauses at the settled shared clock and waits for the exact version and sampled time to render. Its review identifies the document revision, Before/Draft side, shared and sampled times (including held endpoints), scene-local time, camera/venue, aspect, pixel dimensions, and glow/exposure. The PNG contains the rendered show without editor chrome or frame margins. PNG and JSON downloads are explicit, with a matching timestamped stem. Only one still is retained in the preview; failed capture preserves it, a successful replacement releases it, and closing the preview clears it. Moving the live camera or changing versions after image encoding starts does not relabel the historical still. Images remain local and are not yet model inputs.

Portable **review files** bundle that PNG and metadata. Preparing a file exposes an explicit download link; opening one validates it and decodes its image before replacing the retained still. The main stage and independent study can open files as well as the proposal preview, even in Design mode. Imported reviews display their original project/revision and camera/time, clearly labelled **Imported review · integrity checked**. Integrity means the file's bytes agree with its checksum, not that a particular author or model produced them. Import never recalls a camera, changes a show, or applies a proposal. Failure preserves the previous review; cancellation and closing release temporary resources. There is no automatic upload or durable gallery.

The assistant can also inspect where the current draft places the fleet around a captured audience view. It can compare stage-relative directions, overhead placement, camera-frustum counts, and lights that are on, using either the current viewpoint or a saved bookmark. The viewpoint and saved-view list are fixed for that run; inspecting one never moves the user's camera or changes a draft. These are numerical composition aids, not screenshot understanding, occlusion analysis, perceived-visibility judgments, or safety clearance.

Its read-only `compare_viewpoints` tool samples up to four captured views at 2–12 times using the same engine as the artist's comparison panel. This gives the agent measured context for subsequent editable refinements. Summaries describe only the listed samples; they do not establish continuous coverage or rule out brief events between samples.

Refinement preserves the exact unapplied draft across prompts. Shared group transforms translate, rotate around an explicit pivot/axis, and scale selected paths or create position keys at a specified scene time, preserving unrelated channels. Direct drone inspection provides relevant authored keys without paging through the entire scene. Eleven repeatable [evaluation cases](AGENT_EVALUATIONS.md) check precise editing outcomes and preservation on synthetic projects, including large selected path transforms, position keys during incoming blends, and audience-aware lighting refinement. The fixed-view and camera-path cases consume measured tool results, restore brightness only for the relevant selected dark lights, then check sampled counts and unrelated authored content again. Their scripted baseline uses no live provider and makes no model-quality claim.

Success for that adapter is capability coverage: can it perform the same operations as a skilled human, preserve authored work, understand selected objects and time, and recover from failed edits? Restricting the editor to make the assistant simpler would violate this product direction.

## Quality bar

- A direct gesture should have an immediate visual result and a predictable undo step.
- Selection, source, inspector, timeline, and export must refer to the same drone identities and animation.
- Visual polish should improve legibility: restrained chrome, luminous points, readable timing, deliberate motion, and a large working canvas.
- The audience preview should convey human scale and make looking around natural; switching to Design should preserve access to precise spatial editing.
- Controls should be real. Unsupported features should not appear as working buttons.
- Complexity may be exposed when it gives the artist meaningful power. The agent should explain and operate it.
- Creative data may exceed physical flight constraints. Preserve the design and show the relevant findings; do not silently flatten the artist’s intent into a preset.

## Next capability layers

1. **Expert animation depth:** graphical curves and tangents, path handles, editable spatial masks, persistent named groups, multi-channel dope sheets, per-axis interpolation, and better large-selection tooling.
2. **Procedural composition:** a versioned generator/modifier graph, reusable expressions, stagger/distribution tools, text/SVG/mesh sampling, and a constrained script execution environment. The current external TypeScript example establishes the round-trip path but is not an in-app script runtime.
3. **AI operator:** qualify live model behavior against repeatable creative requests; add music/visual context, reusable groups, and persistent revision/run history. The first tool-loop adapter, measured draft review, and explicit recovery of completed proposals across reloads are implemented. Interrupted runs and conversation history are not durable.
4. **Music and delivery:** tempo maps, beat/phrase markers, editable music cues, camera animation, image/video rendering, and optionally Blender asset/render bridges.
5. **Operator-grade planning:** assignment, collision-free routes, continuous validation, launch/landing, site envelopes, hardware profiles, and one real integration.

## Current boundaries

The renderer is Three.js/WebGL, not embedded Blender. There is no Blender bridge, curve graph, arbitrary in-app script runtime, or aircraft control yet. The model connection requires a server API key; a Blender bridge is a proposed extension.

Viewer 360° currently supports a desktop audience camera with local view bookmarks. It does not include VR/headsets, spatial audio, portable venue assets, exported camera animation, or video rendering. Bloom, exposure, and scenery are visual references, not calibrated light output or photometric qualification.

Animation data is much more expressive than the initial recipe schema, but the MVP retains resource limits: 100,000 drone identities, 512 scenes, 30-minute shows, 2,048 keys per edited drone per scene, and bounded file/CSV sizes. Keyframed 100k performance is not qualified. Local browser storage can fill before these maxima; downloadable JSON is the durable handoff.

Motion checks on animated designs are sampled and explicitly incomplete. A 2 Hz CSV can miss short flashes and motion between samples. Every export remains a simulation/design artifact with `flightReady: false`.
