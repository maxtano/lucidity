My working recommendation

Build the device engine and tools first. Start with experience 01; add the smallest useful parts of 03. A standalone chat should earn its place through workflows the host cannot handle well. These samples test interface preference, not real drone reliability or customer demand.

A five-minute comparison

In each view: start over → connect → check → explain → apply. Notice where you want to look, what you need to ask, and whether you trust the result. Then switch views without resetting: the shared record is the part Lucidity should own.

What is deliberately small

One fictional radio mismatch, one allowed change, no real serial connection, no firmware or flight controls. The default replies are scripted. Live mode sends your message, recent lab conversation, and simulated state to Codex/OpenAI and uses your plan allowance. The live browser assistant can prepare a proposal; the Apply button commits it. The real MCP trial can also apply a reviewed proposal through chat.
